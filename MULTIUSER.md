# Мультипользовательский режим (один коннектор на команду)

Позволяет пускать коллег в **ваш** развёрнутый коннектор так, что каждый работает
под **своим** ключом Redmine (своё авторство, свои права), а доступом управляете вы.

Принцип: на сервере хранится карта соответствия **GitHub-логин → { имя, ключ Redmine }**.
При входе сервер по GitHub-логину берёт ключ этого пользователя. Логина нет в карте —
доступа нет.

## Формат карты

Задаётся одной **зашифрованной Build-переменной** `REDMINE_USERS` — значение это
**однострочный JSON** (без переносов строк):

```json
{"vshirokov89":{"name":"Виктор Широков","key":"ВАШ_КЛЮЧ"},"vpetrov":{"name":"Вася Петров","key":"ЕЁ_КЛЮЧ"}}
```

- ключ объекта — **GitHub-логин** (регистр не важен);
- `name` — произвольное имя для вашей идентификации (показывается в `whoami`);
- `key` — Redmine API-ключ этого пользователя (Redmine → «Моя учётная запись» → «Ключ доступа к API»).

## Как задать / изменить

1. Cloudflare → ваш Worker `redmine-mcp` → **Settings → Build → Variables and secrets**.
2. Добавьте (или измените) переменную **`REDMINE_USERS`** типа **Secret**, значение —
   однострочный JSON как выше.
3. Запустите пересборку: **Deployments/Builds → ⋯ → Retry build**. После успешной
   сборки изменения применяются.

Добавить/убрать человека = отредактировать JSON и пересобрать.

## Онбординг коллеги

1. Вы добавляете её в `REDMINE_USERS` (имя, её GitHub-логин, её ключ) и пересобираете.
2. Она добавляет коннектор в Claude: **Settings → Connectors → Add custom connector**,
   URL `https://redmine-mcp.v-shirokov89.workers.dev/mcp`, входит через GitHub.
3. Готово — она работает под своим ключом. Проверка: «вызови whoami» покажет её имя и
   её Redmine-пользователя.

## Что важно знать

- **Вы вписываете ключи сами** — значит, ключ коллеги вы получаете и один раз видите.
  Это осознанный компромисс выбранной схемы. Если нужно, чтобы вы ключи не видели —
  это другая схема (пользователь вводит ключ сам), она сложнее.
- **Где лежит ключ.** Карта `REDMINE_USERS` — это секрет Worker'а (зашифрован Cloudflare
  «at rest»), как и прежний общий ключ. Клиенту не отдаётся, в чат/логи не попадает.
  Технический предел: администратор сервера (вы) при желании может его расшифровать —
  сервер обязан иметь ключ в открытом виде, чтобы ходить в Redmine. Ключ у каждого свой
  и перевыпускается в Redmine в любой момент.
- **Совместимость.** Старый общий `REDMINE_API_KEY` + список `ALLOWED_GITHUB_USERNAMES`
  продолжают работать как запасной вариант для логинов, которых нет в `REDMINE_USERS`.
  Рекомендуется перевести всех (включая себя) в `REDMINE_USERS` и убрать общий ключ,
  чтобы исключить случайную работу под чужим/общим ключом.
- **Доступность Redmine.** Сервер ходит в Redmine из облака Cloudflare, поэтому Redmine
  должен быть доступен из интернета (у вас так).

## Отзыв доступа

Уберите запись пользователя из `REDMINE_USERS` (и из `ALLOWED_GITHUB_USERNAMES`, если
он там был) и пересоберите — доступ пропадёт.
